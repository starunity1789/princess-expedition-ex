## 一、结论：技术上可行，而且比预想的干净

### 1.1 四方没有任何同路径覆盖冲突

四个 MOD 一共覆盖了 **51 个**原版文件，**没有任何两个 MOD 覆盖同一个原版文件**：

| MOD | 覆盖原版文件数 |
|---|---|
| Stellar AI | 27 |
| Planetary Diversity | 15 |
| 皇女的远征军EX | 9 |
| GPM | 0（它靠 `!00_a_*` 另起文件名 + 重定义 ID） |

物理合并不会产生任何「两份文件抢同一个路径」的问题。

### 1.2 ID 级冲突只有三组，其中两组会被删除计划自动消灭

扫过四方 `common/` 下全部顶层定义键，真正被两个以上 MOD 定义的只有：

| 冲突 | 涉及 | 处置 |
|---|---|---|
| `pop_jobs` 的 14 个原版岗位 | PD `zzz_pd_*.txt` vs SAI `02_specialist_jobs.txt` / `04_gestalt_jobs.txt` | **删 PD 的岗位** → 冲突消失，SAI 的研究岗加成恢复 |
| `building_gaiaseeders_2/3/4/pc_gaia` | PD `pd_buildings_overwrites.txt` vs SAI `~stellarai_government_buildings.txt` | **以 SAI 为基准**，删 PD 的这 5 个定义 |
| `decision_baol_life_seed` | GPM `zz_gpm_boal_overwrite.txt` vs PD `pd_replace_decisions.txt` | 见 §2.3 |

另外这些看起来是冲突、其实不是：

- **`on_actions` 的 20 个同名键** —— on_actions 是**合并**而非覆盖，四方的钩子都会执行，这是正确行为。
- **`defines` 的 `NGameplay`** —— PD 改 `DEFAULT_HOME_PLANETS` / `DEFAULT_CLIMATE_LABELS`，本 MOD 改星海共同体三项计时，SAI 用 `NPop` + `NAI`。defines 按键合并，键集不相交。
- `section_templates|ship_section_template`、`message_types|message_type`、`start_screen_messages|part`、`inline_scripts/zones|resources` 等 —— 都是匿名重复块名，不是 ID。

### 1.3 `action.81` 不需要手工合并

GPM 的 `events/!00_a_vanilla_action_overwrite.txt` **整个文件都是注释掉的**，头两行写着：

```
# 4.0 compatible
# REPLACED WITH gpm_pc_changed.2
```

GPM 已经把这段逻辑搬到 `on_planet_class_changed` 上了（`zz_on_planet_class_changed_actions.txt` + `gpm_on_planet_class_changed_events.txt`）。

**处置：原样采用 PD 版的 `action.81`，GPM 那个死文件不要搬进来。** 两者还能正确组合 —— PD 的 `action.81` 执行 `change_pc`，GPM 挂在 `on_planet_class_changed` 上的掷修正逻辑随后触发。

唯一的小缺口：GPM 的 `gpm_pc_changed.2` 只认 `pc_nuked`，不认 PD 的 `pc_pd_nuked_cave` / `_superhabitable` / `_tidally_locked`，这三类星球不会掷到 GPM 的死寂世界修正。可接受。

## 四、Stellar AI：原样搬入

91 个文件 / 1.1 MB，全部照搬，不做任何改动。

**内部加载顺序在合并后依然有效** —— 同一个 MOD 内部，同目录下的文件仍然按文件名字母序读取，
所以 SAI 的 `~` 前缀、PD 的 `zzz_` / `!` 前缀继续生效。盖亚播种者本来就是 `~stellarai_*` 赢，
与「以 SAI 为基准」一致，直接删掉 PD 那份更干净。

唯一要补的是**本地化**：SAI 只有 `localisation/stellaris_l_english.yml`（8.4 KB），没有简中。

## 五、体积与 Git 策略

合并后约 **2.3 GB**，其中 2.28 GB 是贴图：

| | 体积 | 能不能省 |
|---|---|---|
| PD `gfx/models` | 1284 MB | 不能 —— 113 个行星类型的贴图 |
| PD `gfx/portraits` | 591 MB | 不能 |
| GPM `gfx/models` | 400 MB | 大部分能省（陆军、怪物、环境物件都在删除清单里） |
| GPM `gfx/event_pictures` | 12 MB | 能省（事件都删了） |

本仓库 `.git` 现在 37.8 MB，没有 Git LFS，`.gitattributes` 只有 `* -text`。

**建议：脚本进 git，`.dds` 不进 git。** 写 `tools/merge_upstream.py`：

1. 从订阅目录按保留清单拷贝脚本文件（`.txt` / `.yml` / `.gfx` / `.gui`）进 `mod/`，这些进 git
2. 按引用关系拷贝需要的 `.dds` / `.mesh` / `.anim` / `.asset`，这些路径加进 `.gitignore`
3. 失败要大声报错（上游改了文件名就停下），跟 `gen_wargoals.py` 一个思路

这样仓库还是 150 MB 量级，构建出来的 MOD 自包含。换机器重新 clone 之后跑一次即可。

### 为什么元首用事件而不是政体

`auth_corporate` 每 20 年一次寡头选举，而原版 `re_election_allowed` 默认 `no`，现任元首连候选都进不去
（旧的 `auth_dictatorial` 没有 `election_term_years`，所以从来不选举，这个问题 2.8 才出现）。

`advanced_authority_swap` 虽然支持 `election_type = none`，但：

- **不能自建政体**：原版 `is_megacorp = { has_authority = auth_corporate }`，换政体会打断全部巨企机制
- `auth_corporate` 已经有 **10 个** `advanced_authority_swap`，灵能飞升会触发 `is_transcendent_authority`
  那一个，而**同时只有一个 swap 生效** —— 加自己的 swap 就会顶掉灵能飞升的政体加成

所以改成 `on_ruler_set` 钩子重新任命：不碰政体、保住灵能加成、对任何原因的换人都有效。
`set_leader` 会再触发一次 `on_ruler_set`，那时 trigger 不成立，不会递归。

### 周期脚本：银河规则与居住站科技不再挂月脉冲

2.7 及以前，`atb_ex.2` 每月对全体国家补一次银河规则。2.8 改成：

| 时机 | 事件 | 开销 |
|---|---|---|
| 开局 | `atb_ex.1`（`on_game_start`） | 一次 |
| 新国家出现 | `atb_ex.3`（`on_country_created` + `on_country_type_changed`） | 事件驱动，无周期开销 |
| 每年兜底 | `atb_ex.2`（`on_yearly_pulse`） | 每年一次 |

只改成「每年」会有回归：中期刷出来的天灾势力最多一年拿不到非生物船舰体翻倍。事件钩子让它们一出生就有。
年兜底留着，是因为读旧存档不会再触发 `on_game_start`，旧存档里的国家只能靠它补居住站科技。

### 仍然存在：SAI 合金预算的刹车分支对列强不触发

列强的 `country_naval_cap_add = 1000`（大君主再 +1000）让 `used_naval_capacity_percent` 长期很低。
初始 30 艘护卫舰只占 30 点容量，**使用率约 3%，不足以改变这一点**。SAI 合金预算里
`used_naval_capacity_percent >= 1.0` 的三个刹车分支（和平期砍预算 ×0.65、战时 ×0.82、
满容量转投恒星基地 ×2）对列强依然不会触发 —— 列强会把合金持续砸进舰队，恒星基地投入低于 SAI 的设计意图。
这未必是坏事（保底列强本来就该能堆舰队），但如果要按 SAI 的节奏走，需要把海军容量降到中后期能用满的量级。
